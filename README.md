# EnergyRiskLab

Market risk analytics for a natural gas trading portfolio: forward curves, positions,
Value at Risk, Expected Shortfall, backtesting, stress testing and, in later versions,
option and storage valuation, a daily risk report and an interactive console.

**Everything runs on synthetic data.** The market, the desks and the trades are
generated by code in this repository from a random seed. Hub names are public
market locations; no real company, book, position or price is used.

## Quick start

Requires Python 3.11 or later.

```bash
git clone https://github.com/<you>/EnergyRiskLab.git
cd EnergyRiskLab
python -m venv .venv
.venv\Scripts\activate            # Windows (macOS / Linux: source .venv/bin/activate)
pip install -e ".[dev]"
pytest                             # 26 tests
python scripts/run_demo.py         # synthetic market -> trades -> VaR / ES -> backtest -> stress
```

## What is in it

| Module | What it does |
|---|---|
| `erl.data.synthetic` | Daily forward curves: two-factor Henry Hub (mean-reverting level and short-term factor, Samuelson effect, seasonality, higher winter volatility), regional basis with winter premia and correlated shocks, and a cold-snap event |
| `erl.data.trades` | A fictional blotter of fixed-price and basis swaps for three desks |
| `erl.positions` | Trades to exposure by hub and delivery month; mark-to-market |
| `erl.risk.scenarios` | Tenor-matched historical price changes (1-day or overlapping h-day) and scenario P&L |
| `erl.risk.var` | Historical and delta-normal VaR and Expected Shortfall |
| `erl.risk.backtest` | Rolling VaR backtest, Kupiec proportion-of-failures and Christoffersen independence tests |
| `erl.risk.stress` | Historical stress by calendar month: the book as it stands in each of the next 12 months, shifted back by whole years, through every 5-day window of that month; worst window with its long and short legs, main hubs, P5 and median |
| `erl.risk.shocks` | Hypothetical shocks from a small table: Henry Hub parallel and prompt-only moves, basis blowouts by hub, a winter-summer spread shock |

Methods, assumptions and limitations are written up in [docs/model_cards](docs/model_cards).

## How it is built

- Every change goes through a pull request with tests and, where a model changes,
  an updated model card. See [docs/development.md](docs/development.md).
- CI runs lint (ruff) and the test suite on every push.
- Releases are tagged and listed in [CHANGELOG.md](CHANGELOG.md).
- Results are reproducible: same seed, same market, same numbers.

**Use of AI tools.** Parts of this code were drafted with an AI assistant. Every
model is checked against known answers (closed-form normal VaR and ES, hand-built
price changes, textbook test statistics), and the method and its limits are
written up by me in the model cards.
